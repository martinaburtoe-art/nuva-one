# Nüva One Billing — Mercado Pago

Mercado Pago is the first payment provider for Nüva One. The billing domain is provider-agnostic so another provider can be added later without changing tenant entitlements.

## Architecture

`Nüva UI → mercadopago-billing Edge Function → Mercado Pago → mercadopago-webhook → Supabase billing tables → entitlements`

The Mercado Pago access token and webhook secret are server-side only.

## Required Supabase secrets

Configure these secrets in the Supabase project before production activation:

- `MERCADOPAGO_ACCESS_TOKEN` — production access token.
- `MERCADOPAGO_WEBHOOK_SECRET` — secret generated by Mercado Pago Webhooks configuration.
- `NUVA_APP_URL` — `https://nuva-one.vercel.app` in production.

Do not commit any of these values.

## Webhook URL

After deploying the Edge Function, configure the production webhook URL in Mercado Pago:

`https://<SUPABASE_PROJECT_REF>.supabase.co/functions/v1/mercadopago-webhook`

Enable the subscription topics required by the integration:

- `subscription_preapproval`
- `subscription_preapproval_plan`
- `subscription_authorized_payment`
- `payments`

Mercado Pago signs webhook requests with `x-signature`; the function validates the signature before processing the event.

## Test mode

Use Mercado Pago test credentials and the test webhook URL before production. Do not mix test and production credentials.

## Production activation checklist

- [ ] Nüva legal/tributary setup completed.
- [ ] Mercado Pago seller account approved for production.
- [ ] Production access token configured as a Supabase secret.
- [ ] Webhook secret configured as a Supabase secret.
- [ ] Webhook URL registered as HTTPS.
- [ ] Test subscription created and webhook received.
- [ ] Approved payment creates/updates `billing_payments`.
- [ ] Subscription status changes update `billing_subscriptions`.
- [ ] Cancel/pause/recovery flow verified.
- [ ] No payment credentials are stored by Nüva.
- [ ] CI and database tests are green.

## Important

The code is production-ready structurally, but live charging must remain disabled until the legal/merchant account setup and production credentials are completed. The repository intentionally contains no payment secrets.
